# 演讲准备讨论（presentation-prep）

和用户一起把一场演讲从"一个题目"梳理到"一份能直接做 PPT 的简报"。这是**讨论**，不是填表：每个阶段先听用户说，再给出你的整理、建议和追问，双方确认后才进入下一阶段。

这个 skill **只负责想清楚，不负责做幻灯片**。简报定稿后，交给 PPT 生成 skill（见文末"交接"）。

## 两种模式

- **讨论模式**（默认）：用户从一个题目开始，按下面的阶段 0~9 逐步梳理。
- **审稿模式**：用户给了已有的 PPT、大纲、讲稿或文章，要你看看是否符合最佳实践。按文末"审稿模式"做，先给诊断，再针对薄弱的阶段进入讨论模式补齐。

方法来自魏斯曼《演讲大师课》第 1 册《说的艺术》。用到的清单（16 种叙述结构、7 种开场白、7 种外部串词、5 种图表串联）在 [references/weissman.md](references/weissman.md)，进入对应阶段时再读。

## 贯穿始终的四个关键问题

魏斯曼审稿时什么都先不看，只问这四个。每个阶段结束时，都用它们检查一遍刚定下的内容：

1. **目的**：听完之后，希望听众做什么？
2. **听众**：面对的是谁？他们的诉求是什么？
3. **罗马石柱**：撑起整场演讲的是哪几个要点？
4. **结构**：为什么按这个顺序排？选了哪种叙述结构？

## 讨论的规矩

- **一次只推进一个阶段**。每轮最多问 3 个问题；能给选项的用 AskUserQuestion，开放问题直接在文字里问。
- **先给草案，再问意见**。用户给了零散信息，你先整理成一版草案（"我理解的目的是……"），再问哪里不对。不要只抛问题让用户从零写。
- **敢于追问和反驳**。目的太虚（"让大家了解 X"）要追问到"希望他们做什么"；石柱和目的、听众无关要指出来，建议拿掉；主线问题回答不了"so what"要说。
- **用户可以跳阶段、回退**。已经想清楚的阶段，确认一句就过；后面的讨论推翻了前面的结论，回去改，不要硬往下走。
- **简报文件随时更新**。第一个阶段结束就创建简报文件（见文末"产出"），之后每个阶段确认后立刻写回去，让用户随时能看到进度。
- **用用户自己的材料**。用户提到"我写过的文章 / 之前的 PPT / 某个项目"，能读文件就主动去读（在笔记库或项目目录里用搜索工具找），从里面找数据、案例、图，不要凭空编例子和数字。
- 全程用中文，技术名词保留英文。

## 阶段

### 阶段 0：场合

先问清楚，后面所有取舍都依赖它：

- 题目是什么（一句话）？
- 讲给谁（领导、客户、同事、外部活动）？什么场合？
- 时长多少？现场还是线上？有没有提问环节？
- 手上已有哪些材料（文章、旧 PPT、数据、Demo）？

### 阶段 1：目的

- 追问到**一个可观察的行动**：听完之后，听众会批准什么、选择什么、开始做什么、改变什么看法。
- 区分"我想讲的"和"我想让他们做的"。
- 产出：一句话的目的。

### 阶段 2：听众与诉求

- 听众是谁、几类人、谁拍板？
- 他们**已经知道什么**，关心什么、担心什么？对这个题目的立场是支持、中立还是怀疑？
- 对每类听众回答一句"这和我有什么关系"（WIIFM）。
- 预先记下他们**最可能问的 3 个尖锐问题**，阶段 8 要用。
- 产出：听众画像 + 诉求 + 顾虑 + 预判问题。

### 阶段 3：主线问题与一句话主张

- 这场演讲要回答的那个**主线问题**是什么？一般就是听众心里最大的那个问题。
- 你的**一句话回答**是什么？听众只记住一句话的话，应该是哪一句？
- 检查：主线问题是不是听众的诉求（阶段 2），一句话回答能不能推动目的（阶段 1）。
- 产出：主线问题 + 一句话主张。

### 阶段 4：头脑风暴

- 让用户把能想到的材料**全部倒出来**：数据、案例、故事、观点、图、Demo，先不评判、不排序。
- 你帮着补：从用户的已有材料里捞，按"听众关心的诉求"提示还缺哪类素材（证据？案例？对比？）。
- 产出：一份不排序的素材清单，写进简报。

### 阶段 5：归类成罗马石柱

- 把素材归成几组，每组一根石柱，用一句话命名（最好是一个论断，不是一个名词）。
- 和目的、听众、主线问题无关的组，再好也建议拿掉，放进简报的"备用素材"。
- 一般 3~5 根，太多就合并。
- 产出：石柱列表，每根下面挂素材。

### 阶段 6：选叙述结构，排顺序

- 先读 [references/weissman.md](references/weissman.md) 里的 16 种叙述结构。
- 按内容和目的推荐 **2 种**候选，各说一句为什么，以及按它排出来的石柱顺序；让用户选。
- 常见对应：讲演进用历时型；排障、方案汇报用问题-解决型；选型用比较-对比型；多维信息用矩阵图表型；要说服怀疑的听众，考虑以退为进型；要点真的互不相关才用数字榜单型。
- 一场演讲一种结构做主线，单根石柱内部可以嵌别的结构。
- 产出：选定的结构 + 有顺序的主线。

### 阶段 7：开场白

- 按 7 种开场白，结合听众和主线问题，**起草 2~3 个不同类型的开场**（每个 2~4 句），让用户挑或改。
- 开场要简短，目的是抓住注意力、引出主线问题，然后进入第一根石柱。
- 用户惯用的开场类型，可以提醒他换一种试试。
- 产出：定稿的开场白。

### 阶段 8：串联、收尾与提问

- **外部串词**：针对这批听众，标出在哪根石柱上点名、提问、联系时事或当地、引用资料。现场演讲才有这一层，要提前设计，不要临场发挥。
- **图表串联**：石柱之间的过渡页怎么做——缓冲页、色标、基准项（比如每节都出现的路线图）、预期空间。
- **收尾**：回到主线问题和一句话主张，落到阶段 1 的目的，明确请听众做什么。
- **提问预案**：针对阶段 2 记下的尖锐问题，各准备一句话的回答和一个支撑证据。
- **时间分配**：按时长给开场、每根石柱、收尾、提问分配分钟数。
- 产出：串联方案 + 收尾 + 提问预案 + 时间表。

### 阶段 9：逐页大纲

- 把整条主线拆成逐页大纲：每页一个标题（写成论断）、要点、用到的素材、建议的图。
- 当前项目如果有 PPT 模版规范（比如 CLAUDE.md 或 AGENTS.md 里定义的版式），给每页标上建议版式；常见对应：对比 → 对比页，架构 → 架构图页，时间演进 → 时间线页，多要点 → 编号网格页，概念 + 图 → 图文页，等权分类 → 多栏页。
- 最后用四个关键问题把整份简报过一遍，指出还薄弱的地方。
- 问用户：接下来是直接生成 PPT，还是先改简报。

## 审稿模式

用户给的是已有材料时（`.pptx` 先用 pptx skill 或 `python-pptx` 抽出每页标题、要点和讲稿备注；Markdown、文章直接读）：

1. **还原四个关键问题**：从材料里推断目的、听众与诉求、罗马石柱、结构，各写一句。推断不出来的，本身就是问题。
2. **逐项诊断**，每项给"符合 / 部分 / 缺失"和一句依据（指到具体页码或段落）：
   - **目的**：结尾有没有明确请听众做什么？目的是一个行动，还是"让大家了解"？
   - **听众关心点**：每根石柱回答了听众的哪个诉求？有没有只是"我想讲"的内容？预判的尖锐问题有没有被提前覆盖？
   - **主线问题**：开头有没有抛出一个听众关心的问题？一句话主张是否清楚、全篇是否始终围绕它？
   - **石柱**：几根？每根是论断还是名词？有没有重复、过多、与目的无关的？
   - **结构**：属于 16 种里的哪一种？是否和内容匹配（如演进类不是历时型）？页与页之间的关系听众能不能看出来，还是要靠"自己思考"？
   - **开场**：用了 7 种里的哪一种？是否简短、能引出主线问题？
   - **串联**：石柱之间有没有过渡（缓冲页、色标、基准项、预期空间）？现场版有没有为外部串词留位置？
   - **数字榜单**：是否把本有先后或因果关系的内容并列成"N 点"？
3. **输出诊断报告**：先一句总评，再按上面各项列结论，最后给**改进建议，按影响从大到小排**（结构和目的的问题排在措辞和版式前面）。
4. 问用户要不要进入讨论模式，从最薄弱的那个阶段开始改。改完把结果写成简报，同样可以交给 PPT 生成 skill 重做。

## 产出：演讲简报

阶段 0 结束就在当前工作目录建 `briefs/<YYYY-MM-DD>-<题目短语>.md`（目录不存在就创建；用户指定了位置就用用户的），之后每个阶段确认后更新对应小节。格式：

```markdown
---
title: <题目>
created: <YYYY-MM-DD>
stage: <当前进行到的阶段编号>
---

# <题目>

## 场合
场合 / 听众 / 时长 / 形式 / 已有材料

## 四个关键问题
- 目的：
- 听众与诉求：
- 罗马石柱：
- 结构：

## 主线问题与一句话主张

## 听众画像与预判问题

## 素材清单（头脑风暴）

## 罗马石柱
### 1. <论断>
- 素材

## 叙述结构与顺序

## 开场白

## 串联与收尾

## 提问预案

## 时间分配

## 逐页大纲
| 页 | 标题（论断） | 要点 | 素材 / 图 | 模版 |

## 备用素材
```

## 交接给 PPT 生成 skill

阶段 9 用户确认后：

1. 简报 `stage` 改成 `done`，把文件路径告诉用户。
2. 按当前环境里可用的 PPT 生成 skill 交接，告诉它：**以简报的"逐页大纲"为准，每页标题用大纲里的论断，不要自己增删石柱或改变顺序；开场白、过渡页、收尾页照简报做；讲稿备注放进 speaker notes。**
   - 有 `pptx` skill（Claude、GitHub Copilot 都有同名的 PPTX skill）：用它生成 `.pptx`；
   - 有 `frontend-slides` 这类网页幻灯片 skill：生成网页版；
   - 当前项目有自己的 PPT 模版规范：同时遵守它，按大纲里标的版式出页；
   - 都没有：把简报交给用户，说明可以拿去任何 PPT 工具里做。
3. 生成后，可以再用审稿模式过一遍成品，检查做出来的幻灯片有没有偏离简报。

## 开场白（用户没指定话题时）

> 我们按魏斯曼的方法，分几步把这场分享理清楚：先定目的和听众，再找主线问题，然后头脑风暴、归成几根石柱、选结构，最后设计开场和过渡。每一步我先听你说，整理一版给你看，你确认了再往下。
>
> 先说说：这次讲什么、讲给谁、多长时间？手上已经有哪些材料？
>
> 如果你已经有一版 PPT 或大纲，也可以直接给我，我先按书里的方法帮你诊断一遍。
